基础信息

-h/--help/--usage
打印帮助信息并退出。不确定参数名时使用。
--version
显示版本和构建信息。排查兼容性问题时使用。
-cl/--cache-list
显示缓存中的模型列表。确认已下载模型时使用。
--completion-bash
输出可 source 的 bash 补全脚本，启用命令行自动补全。

模型加载与管理

最常用的方式是 -m 指定本地路径，或 -hf 从 HuggingFace 自动下载。
-m/--model FNAME
LLAMA_ARG_MODEL
指定要加载的模型文件路径（.gguf 格式）。这是最基本也最常用的参数。示例：-m models/7B/ggml-model.gguf
-mu/--model-url MODEL_URL
默认: 未使用LLAMA_ARG_MODEL_URL
从 URL 直接下载模型文件。适合 Docker 部署或首次运行。
-dr/--docker-repo [<repo>/]<model>[:quant]
默认: 未使用LLAMA_ARG_DOCKER_REPO
从 Docker Hub 模型仓库获取模型。默认仓库前缀 ai/，quant 默认 :latest。示例：-dr gemma3
-hf/-hfr/--hf-repo <user>/<model>[:quant]
默认: 未使用LLAMA_ARG_HF_REPO
从 HuggingFace 仓库下载模型。quant 可选且大小写不敏感，默认 Q4_K_M；若不存在则回退至仓库首个文件。可自动下载 mmproj，使用 --no-mmproj 禁止。
示例：-hf ggml-org/GLM-4.7-Flash-GGUF:Q4_K_M
-hff/--hf-file FILE
默认: 未使用LLAMA_ARG_HF_FILE
指定 HuggingFace 仓库中的具体文件名，会覆盖 --hf-repo 中的 quant 选择。
-hft/--hf-token TOKEN
默认: 取自 HF_TOKEN 环境变量HF_TOKEN
HuggingFace 访问令牌，用于下载私有或受限模型（如 Llama 系列）。默认读取 HF_TOKEN 环境变量。
--lora FNAME
加载 LoRA 适配器。多个适配器用逗号分隔。示例：--lora adapter1.gguf,adapter2.gguf
--lora-scaled FNAME:SCALE, ...
加载 LoRA 适配器并指定缩放因子。格式：路径:比例。
--control-vector FNAME
添加控制向量，用于引导模型行为（如更友好、更专业等）。逗号分隔多个。
--control-vector-scaled FNAME:SCALE, ...
添加带自定义缩放的控制向量。
--control-vector-layer-range START END
控制向量应用的层范围（包含起止）。精确控制作用于哪些层。
--override-kv KEY=TYPE:VALUE, ...
覆盖模型元数据。类型支持 int, float, bool, str。
示例：--override-kv tokenizer.ggml.add_bos_token=bool:false,tokenizer.ggml.add_eos_token=bool:false
--check-tensors
默认: false（禁用）
检查模型张量数据是否包含无效值。排查模型加载或推理错误时启用。
--lora-init-without-apply
默认: 禁用
加载 LoRA 但不立即应用。后续通过 POST /lora-adapters 动态应用/切换。
--offline
LLAMA_ARG_OFFLINE
离线模式：强制使用缓存，阻止一切网络访问。

上下文与批处理

上下文越大显存占用越高。批处理大小影响 prompt 处理速度，但不影响生成速度。
-c/--ctx-size N
默认: 0（0 表示从模型读取）LLAMA_ARG_CTX_SIZE
上下文窗口大小，即模型一次能处理的最大 token 数量。设 0 表示使用模型训练时的默认值。常用值：4096、8192、16384、32768。值越大消耗显存越多。
-n/--predict/--n-predict N
默认: -1（无限）LLAMA_ARG_N_PREDICT
最大生成长度。-1 表示不限制，直到模型自然结束。设为正整数可控制最多生成多少 token。设为 0 只评估提示不生成。
-b/--batch-size N
默认: 2048LLAMA_ARG_BATCH
逻辑批大小。控制 prompt 处理阶段一次处理多少 token。增大可加速长 prompt 处理，但会增加显存峰值。
-ub/--ubatch-size N
默认: 512LLAMA_ARG_UBATCH
物理批大小。将逻辑批再分割为更小的物理批，在 GPU 上实际执行。通常不需要修改。
--keep N
默认: 0（-1 表示全部）
上下文溢出时保留的初始 prompt token 数量。-1 表示保留全部。仅在交互/无限文本生成模式下有意义。
--swa-full
默认: false（禁用）LLAMA_ARG_SWA_FULL
使用全尺寸滑动窗口注意力缓存。某些模型（如 Gemma 2）需要此选项来正确处理长上下文。
-np/--parallel N
默认: -1（自动）LLAMA_ARG_N_PARALLEL
并发 slot 数。决定服务器能同时处理多少个请求。每个 slot 会占用独立的 KV cache 显存（除非启用统一 KV）。
-cb/--cont-batching/-nocb/--no-cont-batching
默认: 启用LLAMA_ARG_CONT_BATCHING
连续批处理（动态批处理）。允许多个请求共享同一批次，显著提升并发吞吐量。几乎没有理由禁用。
--context-shift/--no-context-shift
默认: 禁用LLAMA_ARG_CONTEXT_SHIFT
无限文本生成时的上下文移位。启用后当上下文写满时自动丢弃早期内容继续生成。

CPU 与线程配置

大多数情况下保持默认即可。只有 CPU 推理或混合推理时需要精细调节。
-t/--threads N
默认: -1LLAMA_ARG_THREADS
生成阶段的 CPU 线程数。-1 表示自动检测 CPU 核心数。通常设为物理核心数（不含超线程）效果最佳。纯 GPU 推理时影响较小。
-tb/--threads-batch N
默认: 与 --threads 相同
批处理/prompt 处理阶段的线程数。prompt 处理可并行度更高，可设为比 -t 更大的值。
-C/--cpu-mask M
默认: 空字符串
CPU 亲和性掩码（十六进制），控制推理线程运行在哪些 CPU 核心上。与 --cpu-range 互补。
-Cr/--cpu-range lo-hi
指定 CPU 核心范围，如 0-7。与 --cpu-mask 互补使用。
--cpu-strict <0\|1>
默认: 0
是否使用严格 CPU 绑定。设为 1 时线程不会被调度到其他核心。
01
--prio N
默认: 0
设置进程/线程优先级。realtime 需要 root 权限。
-1 low0 normal1 medium2 high3 realtime
--poll <0...100>
轮询等级。0 = 不轮询（省 CPU），100 = 最大轮询（最低延迟但占满 CPU）。
-Cb/--cpu-mask-batch M
默认: 与 --cpu-mask 相同
批处理 CPU 亲和性掩码。
-Crb/--cpu-range-batch lo-hi
批处理 CPU 范围。
--cpu-strict-batch <0\|1>
默认: 与 --cpu-strict 相同
批处理严格 CPU 绑定。
01
--prio-batch N
默认: 0
批处理优先级。
--poll-batch <0\|1>
默认: 与 --poll 相同
批处理轮询。
01
--threads-http N
默认: -1LLAMA_ARG_THREADS_HTTP
处理 HTTP 请求的线程数。-1 为自动。高并发场景可适当增加。
--numa TYPE
LLAMA_ARG_NUMA
NUMA 优化策略（多路服务器）。
distributeisolatenumactl
-ncffn/--n-cpu-ffn N
LLAMA_ARG_N_CPU_FFN新增
将前 N 层的稠密 FFN 权重保留在 CPU 上。适用于稠密模型；MoE 专家权重请使用 --n-cpu-moe。

GPU 与设备

单卡用户通常只需设置 -ngl 即可。多卡用户需关注 -sm 和 -ts。
-ngl/--gpu-layers/--n-gpu-layers N
默认: autoLLAMA_ARG_N_GPU_LAYERS
卸载到 GPU 的模型层数。auto 自动适配显存；设为一个大数（如 9999）或 all 表示全部放 GPU；设为 0 表示纯 CPU 推理。
N（精确层数）autoall
-dev/--device <dev1,dev2,..>
LLAMA_ARG_DEVICE
指定用于卸载的设备列表。none = 不卸载。用 --list-devices 查看可用设备。
--list-devices
打印可用设备列表并退出。
-sm/--split-mode {none,layer,row,tensor}
LLAMA_ARG_SPLIT_MODE实验性
多 GPU 拆分策略。layer 最稳定，tensor 可能更快但不稳定。
nonelayerrowtensor
-ts/--tensor-split N0, N1, N2, ...
LLAMA_ARG_TENSOR_SPLIT
多卡时每张卡的模型比例。例如 3,1 表示第一张卡分配 75%，第二张卡 25%。
-mg/--main-gpu INDEX
默认: 0LLAMA_ARG_MAIN_GPU
主 GPU 索引。split-mode=none 时选择使用哪张卡；split-mode=row 时用于中间结果和 KV。
-fit/--fit [on\|off]
LLAMA_ARG_FIT
自动调整未设定的参数以适配显存。开启时会根据可用显存自动缩减上下文大小等。
on\offon
-fitt/--fit-target MiB0, MiB1, MiB2, ...
LLAMA_ARG_FIT_TARGET
--fit 的目标余量（MiB）。每张卡预留多少显存给系统和其他程序。
-fitc/--fit-ctx N
LLAMA_ARG_FIT_CTX
--fit 允许缩减到的最小上下文大小。
-ot/--override-tensor <tensor name pattern>=<buffer type>, ...
LLAMA_ARG_OVERRIDE_TENSOR
覆盖特定张量的缓冲区类型。高级用法，用于精细控制哪些张量放 CPU/GPU。
-cmoe/--cpu-moe
LLAMA_ARG_CPU_MOE
将 MoE（混合专家）权重全部保留在 CPU。可大幅节省显存，但速度下降。适合 MoE 架构模型（如 Mixtral）。
-ncmoe/--n-cpu-moe N
LLAMA_ARG_N_CPU_MOE
只将前 N 层的 MoE 权重保留在 CPU，其余仍放 GPU。比 --cpu-moe 更灵活。
▼

内存管理

--rpc SERVERS
LLAMA_ARG_RPC
以逗号分隔的 RPC 服务器列表（host:port）。
-lm/--load-mode MODE
默认: autoLLAMA_ARG_LOAD_MODE
模型加载模式。auto 在设备支持时使用内存映射；也可选 none、mmap、mlock、mmap+mlock 或 dio。
autononemmapmlockmmap+mlockdio
--mlock
LLAMA_ARG_MLOCK来源未列出，支持状态待核实
本地来源未列出该旧开关，尚未验证当前引擎是否支持。锁定内存可使用 --load-mode mlock 或 --load-mode mmap+mlock。
--mmap/--no-mmap
LLAMA_ARG_MMAP来源未列出，支持状态待核实
本地来源未列出这两个旧开关，尚未验证当前引擎是否支持。可通过 --load-mode mmap 或 --load-mode none 控制内存映射。
-dio/--direct-io/-ndio/--no-direct-io
LLAMA_ARG_DIO来源未列出，支持状态待核实
本地来源未列出这些旧开关，尚未验证当前引擎是否支持。可用时通过 --load-mode dio 使用 DirectIO。
--no-host
LLAMA_ARG_NO_HOST
绕过主机缓冲区，允许使用额外的缓冲区。
--repack/-nr/--no-repack
默认: 启用LLAMA_ARG_REPACK
是否重新打包权重以优化计算。启用可能提升速度但增加加载时间。
--op-offload/--no-op-offload
默认: true
是否将主机张量操作卸载到设备（GPU）执行。
-lzm/--lazy-mode MODE
默认: autoLLAMA_ARG_LAZY_MODE新增
按需读取特定张量，例如逐层 embedding。on 表示按需从磁盘读取，且需要 mmap；auto 只对大于 4 GiB 的张量按需读取；off 表示始终将其保留在内存中。
onautooff
--moe-cache-mib N
默认: 0（禁用）LLAMA_ARG_MOE_CACHE_MIB新增
为保留在 CPU 上的 MoE 专家设置 GPU 缓存大小（MiB）。使用多张 GPU 时，缓存按与层相同的方式依据 --tensor-split 分配。

KV Cache

KV cache 通常是第二大显存消耗（仅次于模型权重）。量化 KV 可显著节省显存，代价是微小的质量损失。
-kvo/--kv-offload/-nkvo/--no-kv-offload
默认: 启用LLAMA_ARG_KV_OFFLOAD
KV 缓存卸载到 GPU。禁用 (--no-kv-offload) 可省显存，KV 会放在 CPU 内存中，但推理速度会降低。
-ctk/--cache-type-k TYPE
默认: f16LLAMA_ARG_CACHE_TYPE_K
K 缓存的数据类型。使用更低精度可大幅节省显存。q8_0 是质量和显存的良好折中。
f32f16bf16q8_0q4_0q4_1iq4_nlq5_0q5_1
-ctv/--cache-type-v TYPE
默认: f16LLAMA_ARG_CACHE_TYPE_V
V 缓存的数据类型。同上。K 和 V 可以分别设置不同精度。
f32f16bf16q8_0q4_0q4_1iq4_nlq5_0q5_1
-cram/--cache-ram N
默认: 8192（-1 不限制，0 禁用）LLAMA_ARG_CACHE_RAM
最大缓存大小（MiB）。-1 = 不限制，0 = 禁用缓存。控制 KV cache 的 RAM 使用上限。
-kvu/--kv-unified/-no-kvu/--no-kv-unified
默认: 槽位数为自动时启用LLAMA_ARG_KV_UNIFIED
统一 KV 缓冲区。所有 slot 共享同一个 KV cache，而不是各占独立的。可提升显存利用率。
--cache-idle-slots/--no-cache-idle-slots
默认: 启用（需要 --cache-ram）LLAMA_ARG_CACHE_IDLE_SLOTS
新任务到达时保存并清除空闲 slot 的 KV cache。需配合 unified KV 和 cache-ram 使用。
-dt/--defrag-thold N
LLAMA_ARG_DEFRAG_THOLD已弃用
KV cache 碎片整理阈值。已弃用。
--kv-unified-per-slot N
默认: 未设置（行为不变）LLAMA_ARG_KV_UNIFIED_PER_SLOT新增
设置每个并行槽位的上下文上限。未设置时行为不变；未同时指定 -c/--ctx-size 时，共享 KV 池大小设为 n_parallel × N。
▼

RoPE 与位置编码

RoPE 相关参数用于扩展模型的上下文窗口。如果模型本身支持长上下文，通常不需要手动调节。
-fa/--flash-attn [on\|off\|auto]
LLAMA_ARG_FLASH_ATTN
Flash Attention。显著减少显存占用并可能加速推理，尤其在长上下文场景。auto 会自动检测是否支持。
on\off\autoonoff
--rope-scaling {none,linear,yarn}
LLAMA_ARG_ROPE_SCALING_TYPE
RoPE 频率缩放方法。默认由模型决定。linear 简单线性外推，yarn 更先进的 YaRN 方法。
nonelinearyarn
--rope-scale N
LLAMA_ARG_ROPE_SCALE
RoPE 上下文缩放因子。将上下文扩展 N 倍。例如设 2 则 4K 上下文模型可用 8K。
--rope-freq-base N
默认: 从模型读取LLAMA_ARG_ROPE_FREQ_BASE
RoPE 基础频率，NTK-aware 缩放使用。增大此值可扩展上下文。
--rope-freq-scale N
LLAMA_ARG_ROPE_FREQ_SCALE
RoPE 频率缩放因子。上下文扩展 1/N 倍。
--yarn-orig-ctx N
默认: 0（模型训练上下文长度）LLAMA_ARG_YARN_ORIG_CTX
YaRN 的原始上下文长度；0 表示采用模型训练上下文长度。
--yarn-ext-factor N
默认: -1.00（0.0 表示完全插值）LLAMA_ARG_YARN_EXT_FACTOR
YaRN 外推混合系数；0 表示完整插值。
--yarn-attn-factor N
默认: -1.00LLAMA_ARG_YARN_ATTN_FACTOR
YaRN 缩放 sqrt(t) 或注意力幅值的系数。
--yarn-beta-slow N
默认: -1.00LLAMA_ARG_YARN_BETA_SLOW
YaRN 高位校正维度或 alpha 参数。
--yarn-beta-fast N
默认: -1.00LLAMA_ARG_YARN_BETA_FAST
YaRN 低位校正维度或 beta 参数。

采样器基础

采样参数决定模型输出的随机性和多样性。温度越高越随机/有创意，越低越确定/保守。
--samplers SAMPLERS
默认: penalties;dry;top_n_sigma;top_k;typ_p;top_p;min_p;xtc;temperature
采样器执行顺序，用 ; 分隔。可自定义采样管道的执行顺序。
-s/--seed SEED
默认: -1（使用随机种子）
随机种子。-1 = 每次不同。设为固定值可使相同输入产生相同输出（用于调试/复现）。
--sampler-seq/--sampling-seq SEQUENCE
默认: edskypmxt
采样器的简化序列表示。每个字母代表一个采样器。
--ignore-eos
忽略结束符（EOS），强制模型持续生成。相当于设置 --logit-bias EOS-inf。
-bs/--backend-sampling
默认: 禁用LLAMA_ARG_BACKEND_SAMPLING实验性
在后端（GPU）执行采样。可减少 CPU-GPU 数据传输开销。
▼

温度与概率采样

--temp/--temperature N
默认: 0.80LLAMA_ARG_TEMPERATURE
温度。控制随机性。0 = 贪婪（总选最高概率），0.7~0.9 适合日常聊天，1.0+ 更随机有创意，2.0 非常随机。
--top-k N
默认: 40（0 表示禁用）LLAMA_ARG_TOP_K
Top-K 采样。只从概率最高的 K 个 token 中选择。0 = 禁用。值越小越保守。
--top-p N
默认: 0.95（1.0 表示禁用）LLAMA_ARG_TOP_P
Top-P（核采样）。从累积概率达到 P 的最小 token 集合中选择。1.0 = 禁用。通常比 Top-K 效果更好。
--min-p N
默认: 0.05（0.0 表示禁用）LLAMA_ARG_MIN_P
Min-P 采样。过滤掉概率低于 P × 最高概率 的 token。0.0 = 禁用。是 Top-K/Top-P 的优秀替代方案。
--top-nsigma/--top-n-sigma N
默认: -1.00（禁用）
Top-N-Sigma 采样。基于标准差的采样方法，保留均值以上 N 个标准差范围内的 token。
--xtc-probability N
默认: 0.00（禁用）
XTC 采样概率；0 表示禁用。
--xtc-threshold N
默认: 0.10（1.0 表示禁用）
XTC 采样阈值；1 表示禁用。
--typical/--typical-p N
默认: 1.00（1.0 表示禁用）
局部典型采样（Locally Typical Sampling）。基于信息论选择"典型"的 token，而非最高概率的 token。
--dynatemp-range N
默认: 0.00（禁用）
动态温度范围；0 表示禁用。
--dynatemp-exp N
默认: 1.00
动态温度指数。
--adaptive-target N
默认: -1.00
adaptive-p 目标概率，用于选择接近该概率的 token；范围为 0.0–1.0，负值表示禁用。
--adaptive-decay N
默认: 0.90
adaptive-p 随时间调整目标概率的衰减率；范围为 0.0–0.99。值越低响应越快，越高越稳定。

重复惩罚

用于防止模型陷入重复循环。如果模型经常重复相同内容，尝试增加这些惩罚值。
--repeat-penalty N
默认: 1.00（1.0 表示禁用）LLAMA_ARG_REPEAT_PENALTY
重复惩罚。大于 1 时惩罚已出现的 token。推荐 1.05~1.2。
--repeat-last-n N
默认: 64（0 表示禁用）
